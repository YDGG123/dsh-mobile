# 多级缓存与磁盘管理

聊天正文缓存用于缩短重复进入会话的等待，并让已经缓存的内容可以离线阅读和搜索。网关仍是历史的权威来源。本地保存的是有限窗口；缓存可能被容量淘汰、系统清理或新的网络快照替换，不承担永久聊天归档职责。

## 代码结构

共享层位于 `shared/src/commonMain/kotlin/com/clarklevis/dsh/shared/cache/`：

| 组件 | 职责 |
| --- | --- |
| `SharedChatHistoryCache` | 类型窗口 L1、异步 Room 读写、epoch/generation/revision 仲裁、搜索、统计及维护门面 |
| `ChatCacheDatabase` | 会话、事件、可搜索正文、三字符索引、独立热度及离线导航目录；替换和容量淘汰使用同一事务 |
| `ChatMemoryCache` | 全网关共享的有界类型窗口 LRU |
| `ChatCacheWindowPolicy` | 最多 400 条事件且不超过 8 MiB 的最新尾部快照 |
| `ChatCacheMemoryEstimator` | 原始事件和投影的保守内存估算，计入工具参数及嵌套 JSON |
| `ChatCacheDiagnostics` | 固定原因、数量、容量和耗时日志 |
| `ChatPrefetchPolicy` | 根据真实打开记录、时间衰减及网关状态排序预加载候选 |
| `SharedOfflineCatalogCodec` | 两平台共用的有界导航目录 JSON；校验会话、工作区、归档和选择，排除正文及连接状态 |

`SharedHistoryStore` 导出、恢复和前插类型窗口，缓存恢复不建立网络 baseline、不恢复网络请求和订阅状态。`SharedConversationStore` 与 `AssistantStreamState` 提供旧会话释放入口。

iOS 的 `ChatHistoryCache` actor 负责路径和 Kotlin suspend 桥接；`AppStore` 在主线程应用历史。`WorkspacePreviewCache`、`WorkspaceFileLifetime`、`ImageAttachmentCache` 和 `AppCacheMaintenance` 负责原生资源文件。

Android 使用进程共享的 `AndroidChatHistoryCache`，`AndroidProjectionActor` 串行应用历史与 UI 投影。`AndroidCacheStorage` 持有全应用唯一磁盘协调器，所有网关共用预算及文件租约；预览、图片、工作区临时下载和更新包均进入其统计。

## 命中与写入流程

1. 选择会话后，平台先更新选择代次，并保护当前及运行中的会话。异步读取最近 80 条缓存事件；旧的选择结果不会应用到后来选择的会话。
2. 共享层优先读类型窗口 L1，未命中后从 Room 读取。完整窗口读取有 single-flight；分页按 `seq` 倒序取页后恢复升序。分页结果不会覆盖 L1 的完整窗口。
3. 缓存先提供显示内容，网络历史到达后由正常历史状态机接管。格式版本不兼容时跳过并失效本地窗口。网络接管后禁止继续拼入旧缓存页，避免复活服务端已经移除的内容。
4. 正常历史变更安排 500 ms 合并写入，完成状态可立即写。只导出稳定历史，不保存临时 `assistant/chunk`。最新尾部最多 400 条事件、8 MiB；裁掉旧事件时置 `hasMore`，将 `nextBeforeSequence` 指向保留窗口首条，而 `persistentCursor` 独立保留。
5. 最新单条事件本身超过预算时跳过该快照，不截断正文，不用更旧内容冒充最新水位；已有磁盘窗口继续保留。之后出现较小的新消息时可再次缓存新的尾窗。
6. 写入前检查 epoch、代次和剩余空间；窗口、搜索索引与 LRU 淘汰在一个 Room 事务提交。失败不影响当前聊天和已经校验的下载源。

`epoch` 隔离清理前排队的写入，`generation` 拒绝同一会话的旧快照，`revision` 隔离读取期间的替换和删除。LRU 使用读取访问时间；最新读取时间先刷新后再决定淘汰。元数据最多保留 4096 个键，达到上限时滚动 epoch，防止清掉删除标记后旧任务复活内容。

原生业务容器另持有保护所有者标记。同一网关重建容器时同步交接所有权，普通保护更新与关闭时解除保护通过串行仲裁提交；旧容器迟到的保护或解除保护不能覆盖新容器。iOS 的提交链跨越 Kotlin suspend，Android 关闭时先等待旧工作退出，再在同一仲裁锁内检查 owner 并解除保护。

## 连接后的热会话预加载

连接成功不会下载所有会话的全部历史。收到 `hello` 和本轮会话列表、当前会话首屏加载完成并空闲 750 ms 后，后台按热度依次预加载非当前、可见且有聊天内容的会话。每轮连接最多尝试 6 个不同会话，单并发，每次仅请求最新 80 条事件、256 KiB；前台正在加载首屏、向前翻页或当前会话正在生成时暂停后续调度。用户操作优先，预加载不建立后台订阅。

热度记录保存在共享 Room 的 `chat_session_heat` 表，与正文分开，包含最近真实打开时间和衰减后的打开次数。打开次数每 7 天减半，最多累计到 64；最多保留全网关合计 4096 条记录。候选得分为：衰减打开次数 × 4、衰减最近打开权重 × 8、衰减网关活动时间权重 × 2，再加运行中 3 分、未读 2 分。同分按会话 ID 稳定排序。没有本地打开记录时主要依赖网关活动时间和状态。预加载、缓存读取及后台响应不增加真实打开次数。

热度用于决定“先取谁”，LRU 用于决定“空间不足时删谁”。后台请求只写冷的 Room 窗口和搜索索引，不暖入 L1，不切换当前会话，不修改未读、活动时间、实时流 baseline 或正常历史分页状态。已有相同格式且水位不低于预加载响应的磁盘窗口会保留，避免最新 80 条替换同水位的更大缓存。用户随后打开已预加载的会话，可以直接从本地显示正文，再由网络确认最新状态；预加载尚未完成、被容量或低空间策略拒绝时，仍走正常按需加载。

清理缓存、内存压力、离开网关和断开连接会停止当前轮次；清理、删除及新前台写入通过 epoch/revision 票据拒绝旧响应落盘。手动清理和遗忘网关同时删除对应热度，普通正文 LRU 淘汰保留热度。数据库由版本 2 迁移到版本 3 时新增热度表，原有聊天正文和索引保留。

Android 预加载仅在 Runtime 的 history lane 空闲时原子发送，忙碌时直接跳过，不排队或合并前台请求。后台来源是客户端本地关联标记，不要求服务器回显新字段；普通前台同会话的 older history 及其错误继续正常处理。预加载等待最多 10 秒，超时会停止本轮；跨自动重连保留 5 分钟单调时间冷却，期间不再发送预加载，避免可选预加载反复触发连接回收。本轮停止后需要新连接才有新一轮资格；冷却到期再由连接或后续状态事件检查恢复，不创建定时重试。

iOS 对不回显请求 ID 的旧协议保留一个待响应隔离槽。用户打开正在预加载的会话时，最新页可直接交给正常前台路由；前台错误终止后释放槽，允许实际重试。已取消或超时的旧响应被隔离，避免旧页冒充向前分页。前台确实需要被隔离的同一会话、或需要向前翻页时，按槽最多触发一次连接重建，收到新 `hello` 后恢复真实前台请求；即使旧响应永不返回，也无需用户手动重连。纯后台 10 秒超时仅终止本连接的预加载轮次，不主动反复重连；迟到数据不回填缓存。

该功能扩大近期常用会话的本地命中和搜索覆盖，并不保证全部会话离线可读，也不主动补全所有旧页。每轮网络响应预算最多约 1.5 MiB；这是请求与缓存验收预算，网关可能返回单条超大事件，客户端会拒绝超预算的缓存，不保证网络实际传输绝不会超出。

## 断线后的主页与离线阅读

连接状态与导航数据分开管理。网络断开、重试连接或认证失败时，主页继续展示原会话列表、工作区、归档过滤和选择；搜索框及搜索词保留，本地正文命中仍可打开。当前阅读内容也保留，包括断线前已经显示的生成前缀。未连接、连接中及失败状态使用红色指示；主页主机栏以当前实际连接状态判断，其他主机的可达性探测不作为当前连接成功的依据。需要网络的创建、重命名、归档和发送操作暂不可用。

同一主机的重连复用现有业务容器，不重建列表、导航和阅读位置。自动连接失败不以全局错误弹窗打断离线阅读；冷启动发现凭据缺失时维持未连接并保留配对入口。真正切换主机时才切换相应容器，所有目录和正文按本地主机 ID 隔离。

Room 的 `chat_offline_catalog` 独立保存导航元数据：会话摘要、归档 ID、工作区、当前会话及工作区选择。目录不包含聊天正文、网络 baseline、订阅、审批或在途请求。版本 3 到 4 的迁移仅增加该表，保留既有正文、搜索索引和热度；两端启动后异步恢复目录，iOS 保留旧偏好数据作为兼容来源。首次磁盘读取结束前，不将尚未初始化的空页面覆盖到目录。

恢复按会话列表、工作区、归档及用户选择分别仲裁。已经到达的新权威列表只阻止其对应旧组件恢复，不能阻止其他缺失组件补齐；用户已经修改的选择优先。缺失、`null`、损坏或部分条目解码失败的列表不当作权威空目录；合法的 `items: []` 才能清空相应旧列表。工作区帧没有归档字段时不清空归档。目录写入有独立 revision/epoch 票据，清理、遗忘或更新目录后的迟到旧写入不能复活旧数据。

离线选择会话和向前翻页只读取本地缓存，不发送 history、subscribe，也不建立等待网络快照的超时。已经加载的正文继续展示；缓存页读完后停止分页，未缓存的会话明确显示连接后可加载，不留下无限 spinner。重连后网络重新确认历史和格式；有效的完整空历史仍可删除旧正文，缓存不能冒充权威内容。

普通“清理聊天缓存”删除正文和索引，保留导航目录，因此列表仍可见，但未保留正文的会话需联网加载。遗忘主机同时删除其正文、热度及目录。正文 LRU 不淘汰导航目录；目录另有全局 8 MiB、64 个主机的上限，单个目录最多 1 MiB、4096 个会话及 512 个工作区。超过单目录边界时跳过该次目录写入并保留旧目录，目录也可能被系统清理，故不能承诺无限数量会话永久离线可见。

## 目录及隔离

| 类别 | iOS | Android |
| --- | --- | --- |
| 聊天数据库 | `Library/Caches/ChatHistory/chat-history-room.db` | 应用私有目录 `databases/chat-history-room.db` |
| 已下载聊天图片 | `Library/Caches/GatewayAttachments/<gatewayID>/` | `cache/gateway-image-attachments/<gatewayID>/` |
| 旧版图片兼容目录 | `Library/Caches/DshMobile/ImageAttachments/` | `cache/gateway-image-attachments/` 中旧条目 |
| 工作区版本预览 | `Library/Caches/WorkspacePreviews/<版本哈希>/` | `cache/workspace-previews/<版本哈希>/` |
| 工作区下载临时副本 | 系统临时目录 `dsh-workspace-files/` | `cache/workspace-files/` |
| Android 更新包 | 不适用 | `cache/updates/`，以及删除中断后待回收的 `cache/.dsh-cache-trash-*` |

数据库主键包含 `gatewayId + sessionId`。预览版本哈希包含网关、会话、路径、大小和修改时间，命中后还检查实际大小及 SHA-256，旧版本或损坏文件不会作为有效预览返回。图片按网关分目录，内存键也含目录，避免不同网关的相同附件 ID 混用。

Android 系统设置中的“清除缓存”通常只处理应用 cache 目录，不会删除 `databases/` 里的 Room 文件；应用内“清理缓存”通过 DAO 删除正文与索引。iOS 数据库位于 Caches，可由系统按缓存策略回收。

清理只访问明确管理的可重建目录。待发图片、上传源、草稿和用户导出目标不纳入此扫描。符号链接不能作为外部文件递归清理入口；分类根和文件操作入口的边界检查需一并保留。

## 容量口径

所有容量均使用 MiB，1 MiB = 1024 × 1024 字节。

| 范围 | 高水位 | 回收目标或策略 |
| --- | --- | --- |
| 全应用受管磁盘 | 384 MiB | 288 MiB；受租约保护的内容允许暂时超过 |
| 聊天 Room 逻辑数据 | 96 MiB | 72 MiB，跨网关 LRU |
| Room 离线导航目录 | 全局 8 MiB 且最多 64 个主机 | 独立于正文 LRU；单主机 1 MiB、4096 个会话及 512 个工作区 |
| SQLite 主文件 | 默认最多约 128 MiB | `max_page_count` = 96 MiB 加 32 MiB 物理余量 |
| 工作区预览 | 192 MiB | 144 MiB；原生写入准入可能更保守 |
| 已下载聊天图片磁盘 | 32 MiB | 24 MiB，默认 7 天过期 |
| 工作区临时文件 | 32 MiB 软预算 | 无使用者的临时文件回收；活跃下载或预览优先 |
| 聊天类型窗口 L1 | 24 MiB 估算且最多 6 个会话 | 全网关 LRU |
| 原生历史和投影 | 每个网关 store 24 MiB 估算且最多 6 个保留会话 | 当前、运行中和其他受保护状态可超过；多个 store 合计另计 |
| 已下载图片原始内存 | 32 MiB | Android 按字节 LRU；iOS 使用 NSCache 成本限制 |
| iOS 可复用会话行高 | 8 MiB 估算且最多 6 个会话 | 按访问时间回收；内存警告清空 |

聊天逻辑容量包含序列化窗口、冗余搜索正文、规范化正文及索引键的估算，不等于 SQLite 页占用。设置中的磁盘统计使用实际分配大小，数据库旁的 WAL、SHM、journal 也计入物理统计。原始事件与投影内存估算计入字符串、嵌套 JSON 和多份管线保留成本；这是淘汰指标，不是 heap 实测，也不代表整个进程内存。

全局受管总量仅包含上表列出的文件目录、Room 主文件和 sidecars，不等于应用全部磁盘占用或进程 RSS。系统及依赖库的其他缓存不在 384 MiB 协调器的管理范围内。

SQLite 使用 bundled 引擎、TRUNCATE journal、`journal_size_limit=0` 和自动回收页。约 128 MiB 限制针对主文件；事务期间 rollback journal、文件系统分配粒度和临时副本仍可增加瞬时物理占用。

128 MiB 剩余空间是写入准入与回收阈值。聊天写入还要求额外事务余量：`max(8 MiB, logicalBytes × 3 + 聊天高水位 / 4)`。查询不到可用空间时拒绝本次聊天缓存写入。其他进程也会消耗磁盘，因此该阈值不构成文件系统硬预留，也不能保证任何时刻都剩余 128 MiB。

## 文件生命周期及清理

预览按不可变版本发布。大文件复制、图片读取和写入在后台执行；预览复制、SHA-256 校验及图片 payload IO 不持有生命周期锁。staging 文件有在途保护，提交时再次核对 epoch，清理前启动的复制或图片响应不能重新发布旧缓存。

使用中的预览、下载及导出副本由租约保护。清空时保留文件供当前使用者完成，结束租约后再删除；此时设置中仍可能显示“使用中”容量。Android 外部播放器和安装器交接使用最长 6 小时的持久租约，避免外部应用稍后打开文件时副本已被清理。更新包与下载中间文件计入全局容量，未受保护的过期更新包默认 48 小时回收。

启动、进入后台、资源写入后和设置页清理会触发维护。维护删除无租约的遗留临时文件及过期图片，iOS 还回收 7 天未访问的预览；两端均按分类及全局水位回收预览。低剩余空间也会触发回收；所有可删内容已回收而受保护内容仍超限时，保留使用者并显示容量压力。活跃临时文件超过 32 MiB 也属于压力状态。

系统内存压力与磁盘清理分别处理。iOS 内存警告、Android `onTrimMemory/onLowMemory` 会释放可重建图片、布局和非保护会话，并调用共享 `trimMemory()` 清空类型 L1。该操作不删除磁盘、不滚动磁盘 epoch，且隔离进行中的读写回填。

## 本地搜索及分页边界

搜索只索引缓存中的 `user/message` 和 `assistant/message` 正文，不索引推理、工具原始参数或输出。三字符及以上使用首个 Unicode 三字符定位候选，再验证完整包含关系；一至二字符直接做包含查询。所有用户输入通过 Room 参数绑定，`%`、`_` 和引号按字面量处理。过长随机文本限制 ngram 数量并回退正文包含查询，避免无界索引。

返回值标记 `coverage=cached-only`。Android 显示最多 50 条本地命中，iOS 最多读取 100 条并按会话展示首个命中；`hasMore` 表示还有结果。没有会话列表元数据的本地命中仍可显示。远端搜索保留独立的请求仲裁；旧网关没有 query 回显时每次只允许一个请求，超时后等待重连恢复，避免 A 的迟到结果污染 B。

打开命中时，当前正常历史已经含目标 `seq` 就直接定位；否则读取附近缓存页，页不存在或不含目标时明确提示命中失效。已经存在最新网络窗口时，旧命中通过独立的只读缓存片段展示，网络窗口、实时同步水位和 stream baseline 继续保留。只允许展示尚未被网络覆盖的旧区间（`hasMore=true` 且目标小于权威窗口首条）或离线缓存。完整网络历史（含空历史）明确不含目标时，旧命中失效；片段展示期间收到这样的完整快照也会退出片段。新快照仍含目标时，iOS 可保留明确标记的缓存片段，Android 会切回正常历史。

“返回最新”优先恢复原来的正常历史；没有正常历史时读取最新缓存页。切换会话会退出片段；iOS 发送消息前退出片段，Android 在只读片段期间禁用发送，需先返回最新。首屏及向前分页默认每次 80 条事件，共享 API 上限 200。事件页可能落在 turn 中间，不能保证呈现完整 turn、完整工具调用链或附件。`hasMore` 同时反映本地剩余页及网关历史缺口，离线时无法补全尚未缓存的部分。

旧页不会无限保存在磁盘。尾窗裁切、网络 snapshot 替换、LRU、手动清理及系统回收都可能移除旧页；搜索覆盖随缓存内容变化。需要长期保留的记录应通过单独的导出或归档功能保存。
